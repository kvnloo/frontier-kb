# HOTL 0.1 — typed topology IR and honest badge decoder

## Claim (one sentence)

Hermes has execution primitives (Kanban, runs, leases, review, goal/judge) but **no machine-readable vocabulary** for an agent network; HOTL 0.1 is a docs/spec IR so badges cannot imply swarm/intelligence/consensus from a drawing.

## Evidence

- Upstream: [NousResearch/hermes-agent#88589](https://github.com/NousResearch/hermes-agent/issues/88589) opened 2026-08-17T19:11:12Z by kvnloo. Open, P3, `needs-decision`. No implementation PR.
- Local package: `t_7432ab2d` — `hotl.md`, `hotl.schema.json`, `issue.md`, README.
- Core: typed nodes/edges, ports, explicit `fanIn` / bounded `dynamicFanOut`, coordination substrate, provenance. Classification is a **set** (pipeline, star, mesh, …) from normalized graph + policy. `swarm` is never inferred.
- Safe Kanban subset: one task per node; dependency edges → parent lists; review nodes → review children; unsupported kinds (message/blackboard/auction/ring/mesh) are visualization-only until a runtime contract exists.
- Non-goals: second scheduler, graph runtime, execution-authority changes, ranking agents.
- 2026-08-19 comment: still proposal; executable subset needs a later maintainer decision.

## Fact vs interpretation

- Fact: issue text and 0.1 schema exist; maintainer has not accepted a module location.
- Interpretation: HOTL is the Hermes-facing name; AODL is the possible public name ([[literature/lit-20260817-hotl-02-spec]]).
